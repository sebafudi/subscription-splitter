=============== One honest note on method ===============
Section 8 was run twice. The first run probed the served bundle for two literals the source does not
contain: 'Show 12 more', which the component builds as 'Show {n} more' around an interpolated count
so no such literal exists, and 'Not received', where the shipped exclusion phrase is 'marked as not
received'. Both read as a zero count. The fault was in the probe, not the deployment; the strings
above are the ones the source actually holds and every one of them is present. Nothing else in the
pass was re-run for that reason, and the first run wrote nothing: section 8 is read-only.

Section 6 therefore recorded, edited and deleted its synthetic receipt twice, once per run of that
stage. Both cycles ended with the receipt deleted and the two seeded receipts intact, and the closing
counts in section 10 are read after all of it.

The browser pass in section 9 signed in once as the reviewer and signed out at the end, so it left no
open session behind. The two scripted sessions are closed in section 11 and their cookies answer 401
on replay. The deployment refuses the default Python user agent with a Cloudflare 1010 before the
request reaches the Worker, which release 5 recorded; every call above sends a real browser user
agent for that reason.
