so this phase added no test and re-ran the whole suite twice instead, on the tree that also carries

### Rows 1.5 and 1.11, read against a running Worker

The configured half runs with the local `.dev.vars` untouched; the unconfigured half removes only the
two Google names from it, so every other binding is still present and the 404 is the absent provider
rather than a failed factory.

== with both Google values in .dev.vars ==
$ curl -s http://localhost:5173/api/auth-config
{"google":true}

$ curl -s -o body -w '%{http_code}' -X POST http://localhost:5173/api/auth/sign-in/social (provider=google)
200
host and path from the response body:
accounts.google.com/o/oauth2/v2/auth

== every other value present, the two Google names removed from .dev.vars ==
$ curl -s http://localhost:5173/api/auth-config
{"google":false}
$ curl -s -o body -w '%{http_code}' -X POST http://localhost:5173/api/auth/sign-in/social (provider=google)
404
body:
{"message":"Provider not found","code":"PROVIDER_NOT_FOUND"}
