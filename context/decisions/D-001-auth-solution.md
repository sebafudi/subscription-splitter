# D-001: Auth solution

- **Decision:** Use Better Auth 1.7.x on the Hono API, running on the Cloudflare Worker, backed directly by the D1 binding (`database: env.DB`, no custom adapter). The Worker requires the `nodejs_compat` compatibility flag because Better Auth uses Node's AsyncLocalStorage for request context. Auth config: `emailAndPassword` enabled with `disableSignUp: true`, so the public sign-up endpoint stays closed; owner and reviewer accounts are seeded by a one-off server-side `signUpEmail` call from a temporary local-only seeding path, not a permanent route, using a second Better Auth instance constructed with `disableSignUp: false` against the same D1 binding. Session cookie is HttpOnly, Secure, SameSite=Lax. Origin and CSRF protection uses Better Auth's built-in checks with `trustedOrigins` set to the app's real origins. Login throttling uses Better Auth's built-in `rateLimit`, backed by the same D1 database, no separate throttling table. The auth schema (`user`, `session`, `account`, `verification`) is a hand-maintained migration, `0001_auth.sql`, because Better Auth's own CLI schema generator needs a live database connection to introspect and D1 can only be reached from inside a Worker, not from a Node CLI process. Each request builds its own Better Auth instance from `c.env`, since a D1 binding only exists inside a request's env in Workers. Routes that need a session use a `requireSession` middleware built on `auth.api.getSession`. Thin app routes (login, logout) wrap `auth.api.*` calls in a try/catch, since those calls throw a Better Auth `APIError` on failure even with `asResponse: true`, and translate a caught error into a JSON response with its own status code.
- **Rationale:** A compatibility spike proved this combination runs cleanly in the Workers runtime against local D1, both under `@cloudflare/vitest-pool-workers` and under a real `wrangler dev` process: seeding, login, session read, wrong-password rejection and logout invalidation all passed as automated tests and were separately confirmed with curl against a live dev server. Better Auth already provides session lifecycle, secure cookie defaults, origin/CSRF checks and login rate limiting, so the app does not need to hand-roll any of them.
- **Rejected alternative:** Standard-primitive sessions, WebCrypto PBKDF2 password hashing plus a hand-rolled sessions table. Rejected because it would require hand-rolling CSRF protection, login throttling and session lifecycle management that Better Auth already provides and that the spike verified running on D1. It stays documented as a fallback if Better Auth is rejected later for other reasons.
- **Review objection + Resolution:** Objection: dependency risk, the auth schema migration is hand-maintained rather than generated, and the spike observed a harness-only unhandled-rejection warning on failed login under `@cloudflare/vitest-pool-workers` that did not reproduce under real `wrangler dev`. Resolution: pin Better Auth and related package versions, keep the auth migration file under this repository's control and treat any future schema change as a manual edit to that file, add automated tests for cross-origin request rejection and rate-limit tripping in the first slice that were not yet covered by the spike, and keep candidate B documented as the fallback rather than discarding it.
- **Affected tests:** Auth integration tests added in the runtime-auth first slice: login sets a session cookie, logout invalidates the session so a later session read is unauthorized, a session read without a cookie is unauthorized, wrong password is rejected, a cross-origin login POST is rejected, and repeated failed logins trip the rate limit.
- **Commit:** recorded when the runtime-auth slice lands.
