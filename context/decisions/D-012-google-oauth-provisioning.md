# D-012: Google OAuth provisioning

- **Decision:** Google sign-in is backed by a dedicated Google Cloud project, `subscription-splitter-auth` ("Subscription Splitter Auth"), created standalone with no parent organization and no billing account. Identity is the only thing this project is for: no paid API is enabled on it, and the application's existing Cloudflare and D1 resources are untouched. The Web application OAuth client registered inside it is the general Google Auth Platform client, not the IAM workforce client and not an IAP brand.
- **Callback path, derived rather than assumed:** Better Auth is mounted at `/api/auth` by the catch-all in `src/server/routes/auth.ts`, and the installed version builds a social provider's callback as `<basePath>/callback/<provider>`. The registered redirect URIs are therefore `<origin>/api/auth/callback/google` for each origin the app is signed in from, and nothing in the application overrides `redirectURI`.
- **Origins:** three. `http://localhost:5173` is `vite dev`, the default `npm run dev`. `http://localhost:8787` is `wrangler dev`. `https://subscription-splitter.sebastianfudalej.workers.dev` is the deployed Worker. The first two are exactly the origins already listed in `APP_ORIGINS` in `.dev.vars`, so the trusted-origin list and the OAuth client agree by construction rather than by coincidence.
- **Audience:** External, kept in Testing. Testing restricts sign-in to explicitly listed test users and avoids Google's verification process entirely, which is the right trade for a portfolio application with one reviewer audience. Publishing the app and requesting verification is deliberately not done. Any claim that public Google login works is therefore false until the audience changes, and the test-user list is what gates a live consent roundtrip.
- **Scopes:** `openid`, `email`, `profile` only. These are the non-sensitive identity scopes that need no verification. Gmail, Drive and any `cloud-platform` scope are out of scope for sign-in and are not requested.
- **Credentials:** environment names are `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. The client id is public and belongs in this record and in `.dev.vars`; the secret exists in exactly two places, `.dev.vars` locally (confirmed ignored by `.gitignore:4`) and the Worker's `wrangler secret` store remotely. It is never written to a repository file, a status file, a screenshot or a log, and any client JSON downloaded from the console is deleted after the values are transferred.
- **Rejected alternative:** provisioning through `gcloud iam oauth-clients create` or an IAP brand. Both are automatable and both are the wrong object. The IAM client is a workforce identity federation client and IAP brands govern Identity-Aware Proxy, neither of which produces the web OAuth client a Better Auth social provider consumes. A search of `gcloud services list --available` found no first-party API that manages Auth Platform branding, audience or web clients, so the authenticated Cloud Console is the supported surface and the remaining work is a manual console step rather than a scripted one.
- **Status:** the project exists and the callback contract above is fixed. The consent screen, the Web client and the credentials are **not yet created**: the console steps are blocked on an authenticated browser session, and the exact remaining actions are recorded in `context/checkpoints/g02-oauth-provision.md`. This record is completed in place, not rewritten, once the client id exists.
- **Affected tests:** none yet. Provider configuration and the OAuth failure paths are covered under the implementation goals, not this one.
